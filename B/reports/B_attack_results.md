`sanity_attack.py` 已接入 A 组的 `patch_kgw_cpu`。新版原始水印 200 条全部检出，逐 token 指纹 `5d98d773dd` 与 A 组 README 一致，原有的检测环境不匹配问题已解决。

### 改写后人类文本的误报对照

改写模型未添加 KGW 水印，因此人类文本即使经过 AI 改写，也不应被判为带有这把 key 的水印。使用同一 CPU 绿名单补丁、完整文本、未去重 z-score 和固定阈值 z>4，结果如下；改写后的统计只包含有效记录。

| 名义改写比例 | 有效样本数 | 误检数（z>4） | 实测误报率 |
|---|---:|---:|---:|
| 未攻击 | 500 | 0 | 0.0% |
| 25% | 199 | 0 | 0.0% |
| 50% | 200 | 0 | 0.0% |
| 100% | 200 | 0 | 0.0% |

改写后合计 599 条有效记录中没有误报；全部 600 条（包括 1 条无效记录）也均未超过 z=4。三档改写来自同一批 200 篇文章，不是 599 篇独立文档。观察到零误报不代表真实误报率为零。

这里是 B9 检查结果，不代表已经验证 1% 误报率或 e-process 有效性。不同长度、去重、统一误报率及最小所需长度分析，以及固定长度、peeking、e-process 各自的误报率和置信区间，由 C 组完成。攻击文本自然变长或变短，不补齐、不截断；本次水印攻击长度为 435–661 token，因此上表中的水印检测结果也不是固定相同长度的公平比较。

## 验证和限制

全部 1200 条通过字段契约、三档完整性及无重复检查、改写位置嵌套、text 与 token_ids 精确对应、prompt_ids 与新版原记录一致、未改写片段（含末尾半句）保持不变的检查。

抽查新版前五篇水印文本，发现日期变化、最多三年变至少三年、事实关系变化等问题；12 条拒绝决定见 `configs/attack_manual_review.json`。其余文本尚未逐篇人工复核，自动相似度不能证明语义完全不变。
